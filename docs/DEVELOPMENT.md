## Commands

```sh
npm start
npm run dev
npm run build
npm run engine:install -- /path/to/noise-rng-evidence.zip
npm run engine:setup
npm run engine:build
npm run engine:registry
# Reuse the captured native classes while changing only the browser bridge:
npm run engine:build -- --reuse-native-inputs
# Re-export registries from captured native dependency inputs:
npm run engine:registry -- --reuse-native-inputs
# Export native schemas for a saved authoring pack (defaults to the upstream fixture):
npm run engine:schemas -- /path/to/your/pack
```

`IRIS_PACKS_DIR` identifies the parent of pack folders. The default is `packs/` under the application. Set `HOST`, `PORT` and `IRIS_STUDIO_TOKEN` in `.env` when needed. Binding outside loopback requires a token of at least 32 characters. The application serves code and pack data only; preview seeds, coordinates and generated buffers are not sent to the server.

Automatic engine-tool setup currently supports Linux x64 and uses SHA-256/SHA-512 pinned JDK, Gradle and Maven archives. Other environments can provide `IRIS_JAVA_HOME`, `IRIS_GRADLE_BIN` and `IRIS_MAVEN_BIN`. Building the engine also needs git, curl, tar and Python 3. Source checkouts must match the pinned, unmodified Git revisions. The generated module, corresponding-source ZIP and license files remain local ignored build outputs.

## Texture rendering and ownership batch — 2026-10-21

TextureAtlas now examines each referenced animation frame at most once (stopping once blended alpha is established), so a later transparent frame cannot remain in an opaque mesh or cause incorrect full-cube occlusion. Unreferenced frames do not affect classification. Every initial/animated upload copies the four edges and corners to an allocated one-pixel gutter; transparent frames clear previous border pixels. Duplicate concurrent adds share a promise, and failed metadata/read/upload admission does not consume atlas space. Animation timing uses bounded cumulative endpoints and binary search, skips redundant uploads of repeated source indices, and explicitly rejects unsupported interpolation. Existing supported default frame-layout behavior is retained; complete Minecraft layout semantics are unqualified.

ResourcePackStack validates PNG header dimensions before createImageBitmap. Limits are 8 MiB input, 4,194,304 pixels, width 4,096 / height 16,384 and 64 MiB RGBA bitmap accounting across pending and retained decodes per stack. Accounting excludes browser implementation overhead and the separate bounded atlas canvas/GPU texture. Malformed metadata and decode failures evict failed promises and release admission. Disposing marks the stack closed immediately, closes late decodes, and is idempotent. Atlas disposal rejects delayed additions before touching the resized canvas.

Pack replacement pauses the previous atlas before closing its source bitmaps, preserving its last GPU image while the new mesh loads. A replacement revision prevents an older asynchronous handoff from overwriting the current stack or posting a stale completion. Generated voxel contents remain owned separately.

Focused command: `node tools/checks/texture-pipeline-smoke.mjs`. One controlled canvas/device/bitmap check uses an eight-pixel animation, a static pixel, one actual baker/mesh-worker quad and five header-only budget admissions; it allocates no large pixel arrays. Timing/gutter/transparency, failure/retry and delayed-disposal assertions pass, as do syntax/patch checks. The first harness run had an incorrect cycle-wrap expectation for a repeated frame inheriting the default duration; the expectation was corrected. This is implementation evidence with doubles, not real browser/WebGPU or Minecraft parity. No engine rebuild or broader checks ran.
