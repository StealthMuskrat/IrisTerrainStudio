# Third-party code and assets

The repository includes original application/tooling code and the user-supplied specification. No F8thful, vanilla textures/models or Minecraft binaries are committed. An optional local installer provisions the previously verified experimental VolmLib/TeaVM noise module into an ignored generated directory, together with corresponding source, licenses and notices. A development distribution containing that module must retain those materials. The local development engine compiles original Iris/VolmLib terrain paths; complete supported-path and release qualification remain unfinished. Four original native starter JSON files are tracked with their GPL license and source notice under `packages/iris-resources/starters/terrain3d/`.

Use `.local-assets/` for authorized development inputs and `.upstream/` for pinned development checkouts. Both are ignored by Git. Record input hashes and provenance before creating derived rendering bundles. Local access to an archive does not itself establish redistribution permission.

The development-only `tools/portability-probe` harness and its original JDK compatibility adapter are GPL-3.0-or-later. The adapter implements the MD5 integer algorithm described by RFC 1321 and the narrow UUID/UTF-8 behavior exercised by RNG; it does not vendor OpenJDK implementation code. CI fetches exact VolmLib source after digest verification and retains its source/license with generated experiment artifacts. No license for unrelated original project components has been selected. Upstream licensing observations are not a complete licensing assessment of a future combined application.

The local rendering-dependency pipeline creates browser-downloaded Studio ZIPs from user-loaded packs. It copies retained asset bytes unchanged, includes original source metadata and conventionally named notices/licensing directories under `sources/`, and records source archive and retained-file hashes. These downloads are for authorized local reuse; the application does not upload or publicly distribute them. Notice discovery does not establish that every licensing obligation has been found. The supplied F8thful and exact vanilla baseline are now provisioned locally. Their identities and selected real rendering checks are recorded in the [asset evidence](evidence/f8thful-defaults-2026-10-23.json). Complete client rendering and distribution rights remain unqualified.

The pinned client rendering input captures contain numerical/identity metadata (model matrices/seeds/offsets, compact state/face profiles, tint rules, biome climate/colors and math tables). The original classes, decompiled reference sources and asset bytes remain local development inputs. Rendering modules port the inspected algorithms; this provenance record does not establish production distribution qualification. See [fluid/tint boundaries](research/MINECRAFT_FLUID_TINTS.md) and their input/evidence hashes.

The shared `Math.round` adapters retain OpenJDK 25 notices under GPL-2.0-only WITH Classpath-exception-2.0, with original corresponding source and legal notices in the generated source archive. This is separate from the earlier original UUID/UTF adapter described above.

The current development engine pins Iris 4.3.5 (`c3359e0a16438b1bb8468901c6171dcefdf63f7f`) and an explicit API-synchronized VolmLib candidate (`210705c5ab1321dc74b86b48457fd6d5e0452944`). The shipping dependency is still unqualified. The four tracked starter resources retain their original 4.3.4 attribution and are byte-identical to the corresponding 4.3.5 fixture; they are not a second runtime engine. Corresponding source and notices remain attached to the generated current module. Optional provisioned local default assets enter distributions only by explicit build flag; this does not grant redistribution permission.
