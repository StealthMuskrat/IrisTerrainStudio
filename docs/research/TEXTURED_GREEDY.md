# Conservative textured cube merging

The renderer can now combine compatible exposed textured cube faces while repeating each original sprite once per stored cell. Admission is deliberately conservative: every rendered model in the snapshot must be a static opaque unit cube or empty, with no fluid, offset or contextual plan. Each cube has exactly six distinct outward square faces, full-sprite orthogonal UVs and a finite atlas rectangle. Partial, cutout/blended, rotated/overhanging element geometry and cropped UVs keep the existing emitter. Mixed snapshots with these models do not use this optimization.

Baking retains each face's sprite rectangle. The worker checks cube geometry/orientation once per immutable model snapshot, then groups visible faces by direction/plane, sprite, UV orientation, resolved color and material parameters. Per-section 256-entry masks combine equal profiles. Native face visibility, per-cell model selection, tint and flat colors still run in their original positions; no block-state registry enumeration is added. Section clip/halo keys and cache ownership remain unchanged.

Merged faces carry unwrapped tile coordinates and one validated sprite rectangle per emitted quad. The shader wraps coordinates within that rectangle and uses explicit gradients from the unwrapped coordinates, preserving local mip derivatives across tile seams. The sampler and animated atlas remain shared with ordinary faces. The WGSL `textureSampleGrad` contract is described in the [W3C specification](https://www.w3.org/TR/2026/CRD-WGSL-20261021/#texturesamplegrad). Fog distance now comes from interpolated world position in the fragment, avoiding a dependency on how many vertices tessellate a coplanar surface. Full Minecraft fog, raster/edge equivalence and actual shader execution are not qualified here.

An internal material flag marks repeated sprites while retaining the native back-face-cull policy. Rectangle buffers are independently validated before GPU upload or picking, charged in the section cache, and included in the existing GPU allocation owner. Unchanged capacities are reused and disposed with that owner. Cached worker arrays are never transferred directly; fresh combined arrays preserve later clip reuse. Missing/invalid rectangle metadata refuses before upload.

The high owner bit used by diagnostic cell rectangles also identifies admitted textured cube rectangles. Picking wraps UVs through the same sprite rectangle, samples current atlas alpha, resolves the actual underlying cell and outlines its unit face. The stored block, biome, region and model identity continue to come from that cell. This does not claim exact shared-edge/coincident-surface behavior under every rasterizer.

A 24-cell authored box changes 52 exposed faces to six quads: geometry/material/picking transport changes from 20,384 to 2,448 bytes including the new rectangle data. Twelve selected rays preserve block ownership, unit-face selection and selected 8 × 8 texel coordinates through rotated/mirrored UVs. Surface coverage, clip/cache reuse, material-color boundaries, unsupported-model fallback, retained arrays and malformed metadata pass through actual Node mesh workers. The real upload/binding methods run against a controlled device for allocation reuse and pre-upload refusal. Existing small diagnostic, region-cell and section-cache checks also pass. These are focused operation/byte results, not a GPU timing or appearance qualification. See [evidence](../evidence/rendering-deployment-2026-10-23.json).

Actual WGSL compilation/rasterization, animation/mip/edge integration, all model options and measured browser/GPU performance remain unverified because the execution environment's browser/preview route is unavailable. Native terrain/module/source identities remain unchanged by this renderer work. No terrain generation, registry export/state sweep, broad suite or GitHub workflow ran for this rendering/deployment checkpoint.
