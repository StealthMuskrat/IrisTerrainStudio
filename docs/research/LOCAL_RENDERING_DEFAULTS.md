# Local default-asset provisioning and vertical region inspection

The specification permits a local provisioning workflow when distribution permission is unavailable. `tools/assets/prepare-defaults.mjs` consumes explicitly supplied local vanilla/override ZIPs. It neither downloads a replacement F8thful archive nor claims that an arbitrary archive is the intended supplied input. It records each input hash and writes two optimized original-path archives, keeping baseline and default roles separate for custom replacement. Baseline dependencies introduced only by override models are retained. Original metadata, applicable overlay assets, model/texture/animation dependencies and notices survive; unrelated files and inactive overlay contents are omitted. Native target/filter resolution still runs at load time. Missing references, unsupported dependency models, size limits and existing destinations refuse before publication. Inputs are unchanged. Default roots are baseline blockstate filenames, not enumerated registry states. Optional explicit roots bound a supported subset.

The server validates the two fixed archive names, sizes, SHA-256 values, regular-file types and target descriptor once per process. The authenticated catalog and fixed-role download routes expose no arbitrary file paths. The browser bounds streaming downloads, verifies hashes and opens packs with the existing loader. Installation defaults enter the existing role/priority owner after authentication. Enable/disable choices persist as small settings records; their archives stay server-provided. Custom replacement omits only default overrides. Session changes work when browser storage is unavailable. The standalone builder includes local assets only with an explicit flag and writes a validated owned snapshot; normal builds omit them. Generated local/default files remain ignored by Git.

Stacked terrain inspection now retains compressed vertical region spans. The pinned original `DimensionStackLayout.layerAt` can change at rendered or gap endpoints; original `Engine.getRegion(x,y,z)` resolves those bounded intervals, including its overlap/gap precedence. Adjacent equal regions coalesce. Each column stores offsets, start heights and palette IDs, without a height-expanded index array. Actual span lookup drives individual-cell inspection and both region-color emitters, and all three typed buffers count toward retained generation-cache charges. Existing unstacked columns keep their original representation. Host subterrain occupancy can override layer ownership, so that combination explicitly omits optional region metadata until its occupied raster is connected; generated material data is retained.

Focused evidence uses one authored asset block type and two tiny source packs, actual authenticated HTTP and standalone opt-in packaging, plus four stored region cells. Ten selected region queries execute the original JVM Engine default for one native stacked pack and match actual Wasm/worker/client lookup. Its region transport occupies 6,148 bytes versus 65,536 for expanded indices, using 1,536 boundary queries rather than 32,768 voxel queries. Cache reuse, release retention, malformed metadata and both actual mesh emitters pass. No registry/state sweep, comprehensive suite or GitHub workflow runs. Browser/GPU execution, authentic F8thful input, native reference provenance and full project qualification remain unverified.
