# Native surface hydrology planning map

The host-dimension Surface hydrology field displays the feature type selected by original Iris `HydrologyColumnSample.primarySurfaceLayerOrNull()`. It reads actual published column snapshots. It does not reconstruct a river, interpolate terrain, simulate fluids or combine underground/deep-fluid layers into a surface answer. A native shore/grading column can belong to a surface feature even when that column contains no fluid.

Each grid center is floored to a whole-block X/Z coordinate. The native runtime prepares each distinct sampled chunk once, then every requested snapshot must be available. Category zero explicitly means no original primary surface feature; other category labels come from original surface feature enum values. The retained metadata identifies the selection and sampling rules. Map analysis/export uses the stored sample values and continuous grid centers; the sampling rule explains their underlying integer block coordinates.

One owned matter scope supplies original containment inputs if required, and a generation lease/execution scope surrounds preparation and sampling. The existing root/call/sparse-carving admission applies to the entire map. Limits are 256 samples per axis and 256 blocks in each window axis, with the existing world-coordinate margin. These are resource policies, not runtime/heap or full-options qualifications. Only active native hydrology dimensions are admitted; unsupported, unavailable or over-budget requests fail explicitly.

The worker validates the complete categorical response and transports Float64 indices, categories, native metadata and source labels through the existing client cache. It captures diagnostics and releases the native context before publishing a result. Native execution is synchronous, so cancellation terminates the worker. Current unsaved dimension/open edits and binary pack resources use existing snapshot capture/ownership. Map labels describe planning data; material rendering remains a separate registered Overworld path.

Focused qualification uses five selected samples in three tiny windows, including an occupied standing pool, a negative-coordinate control and negative fractional centers. It checks the actual JVM/Wasm and worker/client paths, bounds/inactive-runtime refusal, recovery/release and controlled cancellation. Actual browser interactions, WebGPU colors/layout, every feature/option, deep/underground containment and complete terrain/rendering/release qualification remain open.
