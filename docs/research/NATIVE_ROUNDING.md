# OpenJDK rounding at native browser call sites

The procedural ruin comparison exposed an arithmetic boundary shared by other original Iris and VolmLib classes. TeaVM 0.16.0's float and double `Math.round` implementations round negative half values away from zero. OpenJDK 25 rounds ties toward positive infinity. This can change negative-coordinate noise decisions and fitting results.

`NativeRoundingPlugin` redirects the original `Math.round` and `StrictMath.round` float/double calls in Iris and VolmLib classes to `WorkerJdkRound`. The two pinned Minecraft rotation math classes use the same boundary. Other Java math functions, JavaScript rendering math and unrelated JDK code are unchanged. The adapter follows the original OpenJDK bit/exponent/significand operations, including signed zero, subnormals, precision boundaries, infinities, NaNs and saturated conversions. Its original copyright, license and complete corresponding OpenJDK source accompany the module.

The initial ruin-only binding moves into this shared plugin. Exact checks retain eight generator/four shape calls, and additionally require nine original CNG and six original HexagonalNoise calls. The controlled diagnostic requires one call of each overload. Other transformed classes and call counts are build metadata; they are not behavioral comparisons or statements of caller qualification. Plugin ordering no longer determines whether the pinned ruin checks see original calls.

The owned diagnostic accepts only exact 16/8-character hexadecimal IEEE input patterns. It runs two direct Math-call probes through the actual compiler boundary and, for finite bounded doubles, three original `CNG.fit` equal-range overloads. The JVM reference compiles the same probe without a browser compiler plugin, so it calls the original JDK and original CNG methods. Native double results remain decimal strings rather than passing through JavaScript Number.

The focused check uses 26 authored double/float pairs and the corresponding bounded CNG fitting probes. It includes negative half ties and adjacent values, signed zero/subnormals, large precision/integer boundaries, infinities and NaN payloads. Malformed input refusal and subsequent recovery are checked. No registry, world or terrain is needed for this arithmetic check. The cached native ruin fixture is separately replayed through the rebuilt module. See [evidence](../evidence/native-rounding-2026-10-23.json).

This corrects the identified browser arithmetic boundary. It does not resolve the separate unchanged native checksum discrepancy, qualify every transformed caller or establish complete noise/terrain parity. Full native/browser/release and browser/GPU/performance gates remain open. Comprehensive program verification remains deferred until implementation is complete.
